측정일 2026-11-02. `처음`은 커밋 787ddcd, `지금`은 브랜치 harden-from-redteam이다.
파이썬 3.12, 윈도우 PC 한 대에서 쟀다. 시간은 벽시계가 아니라 CPU 초(`thread_time`)다. 모델은 `claude-haiku-5-5`다.
여기 있는 숫자는 모두 이 조건에서 잰 값이다. 다른 PC에서는 시간이 달라진다.

## 4. 처리 시간

규칙 단독, 입력을 한 번 검사하는 데 쓴 CPU 초다. `thread_time`의 눈금이 약 0.016초라 그보다 작은 값은 0.02 미만으로 적는다.

| 입력 | 처음 | 지금 |
|---|---|---|
| 공백 1,600자 | 20.1 | 0.02 미만 |
| 탭 1,600자 | 37.1 | 0.02 미만 |
| 줄바꿈 1,600자 | 53.6 | 0.02 미만 |
| 공백 2,000자 | 82.6 | 0.02 미만 |
| 줄바꿈 2,000자 | 213.8 | 0.02 |
| `ignora` 되풀이 2,000자 | 0.05 | 재지 않음 |
| `ignora` 되풀이 20,000자 | 재지 않음 | 0.52 |
| `give all ` 되풀이 20,000자 | 재지 않음 | 0.67 |

처음 코드는 공백 덩어리에서 시간이 길이의 세제곱에 가깝게 늘었다. 앞말 선택과 `\s*`가 겹치고, `(^|\n)\s*`가 줄마다 다시 시도됐기 때문이다.

지금은 길이 상한까지 채운 입력을 재도 시간 상한 안에서 끝난다. 시그니처 앞머리를 되풀이한 46종을 입력 2만 자, 문서 5만 자로 채운 92가지 중
최악은 문서 모드 `give all ` 되풀이로, 시간 상한 1.2초에 닿아 차단됐다. 시간 초과로 막힌 것은 이 1가지다. 입력 경로에서 시간 초과는 없었다.

## 5. 블라인드 측정 방법

**블라인드 측정**은 규칙을 고치는 쪽이 보지 못한 문장으로 재는 것이다. 본 문장으로 재면 그 문장에 맞춘 규칙의 점수만 오른다.

1. 문장을 만드는 쪽과 규칙을 고치는 쪽을 나눈다. 공격 문장과 정상 문장을 함께 만든다.
2. 코드를 고정한다.
3. 문장을 실제 글 가운데에 끼워 넣어 한 번만 잰다. 규칙만, 규칙과 LLM 둘 다 잰다. 정상 문장은 짧은 글로도 잰다.
4. 숫자를 그대로 적는다.
5. 잰 뒤에 그 묶음을 보고 규칙을 고치면 그 묶음은 더는 블라인드가 아니다. 다음 측정에는 새 묶음을 만든다.

`eval_data/`의 두 묶음이 이렇게 나왔다. 1차 묶음(공격 92, 정상 82)은 이 가드를 다른 프로젝트에 옮겨 처음 레드팀을 할 때 만들었고,
2차 묶음(공격 80, 정상 80)은 1차 결과로 규칙을 고친 뒤 새로 만들었다.

**실제로 블라인드였던 측정은 2차 묶음을 처음 쟀을 때 한 번뿐이다.** 다른 프로젝트의 사본에서 쟀고, 그 프로젝트 전용 규칙과 프롬프트가 있어 이 저장소의 코드와 같지 않다.

| 그때 측정 | 규칙만 | 규칙+LLM |
|---|---|---|
| 2차 공격 80 | 6/5/69 | 70/10/0 |
| 2차 정상 80, 공고에 끼움 | 0/0/80 | 2/9/69 |
| 실제 구청 고시 97건 | 0/0/97 | 0/0/97 |

**위 1~3절의 묶음 재측정은 블라인드가 아니다.** 두 묶음 모두 이미 본 문장이고, 이 저장소에 공개되어 있다. 규칙이 나빠지지 않았는지 보는 회귀 확인으로만 읽는다.
공개하면서 전화번호를 빼고, 다른 프로젝트의 내부 필드 이름을 일반 이름으로 바꾸고, 건물 이름 하나를 바꿨다. 그래서 그때와 같은 문장이 아닌 것도 있다.
새 코드의 성능을 말하려면 새 묶음을 만들어 재야 한다.

## 6. 규칙이 못 막는 것

규칙 층은 난독화, 역할 표시, 필드 이름, 명령형 문장까지 잡는다. 아래는 정상 글과 모양이 같아 정규식으로 못 막는다. 낱말을 늘려 쫓으면 오탐만 는다.

- 위조 사실: 평서문으로 적은 거짓. LLM 층도 주제에 맞게 쓴 거짓은 글만 봐서는 알 수 없다.
- 바꿔 말하기: 낱말을 피해 같은 뜻을 쓴 글.
- 업무 문체의 작성 지시, 권위 사칭, 여러 문장에 나눠 쓴 지시.
- 거꾸로 쓴 글, 표 밖 언어.

이 유형은 뒤 단계가 맡는다. 뽑은 값을 원문과 대조하는 출력 검증, 데이터를 바꾸기 전의 사람 승인이다. 자세한 내용은 [integration.md](integration.md).
